How the services talk to each other

One cluster, three loops. Documents move along the teal path (event-driven, eventually consistent), chat along the blue path (request/response), and code reaches the cluster along the dashed grey path (git → pipeline → cluster). Every arrow is labeled with what crosses it.

Upload path

event-driven · eventually consistent

The upload itself is the trigger: S3 tells EventBridge, EventBridge invokes the ingest Lambda, the Lambda records "uploaded" in DynamoDB and writes one DocumentUploaded line in Kafka, then walks away. Three worker teams read the logbook at their own pace. The embedder chunks and embeds into Qdrant; the summarizer asks the LLM (through the gateway, so it gets the same vLLM-or-Bedrock routing as chat) and writes summary and tags to the catalog; the notifier turns SummaryReady into an SNS alert. If the GPU node is off, the summarizer's lines simply wait in the logbook.

Chat path

request / response

Two doors, one gateway. The public door is the ALB with TLS and a bearer key; the private door is Open WebUI over the tailnet. Both land on the gateway, which speaks the OpenAI contract: model=llm goes straight to vLLM, model=docs first retrieves top-k chunks from Qdrant and stuffs them into the prompt. When the GPU node is scaled to zero or unhealthy, the gateway falls back to Bedrock and says so in the response. Every completed chat becomes a ChatCompleted line in Kafka for the usage and cost dashboard.

Delivery & ops

git → pipeline → cluster

A push runs GitHub Actions: lint, tests, image build, vulnerability and secret scans, and a Terraform plan. On merge, Actions pushes images to ECR (tagged with the git SHA) and applies Terraform to AWS using a short-lived OIDC role, never a stored key. Argo CD, living inside the cluster, pulls the manifests and makes the cluster match git. Karpenter creates the GPU node the moment vLLM's pod asks for one and removes it when the pod is gone; the nightly Lambda terminates any GPU that survived anyway.

Not drawn, on purpose. Prometheus scrapes /metrics from every pod (vLLM, Kafka, the workers) and Loki collects every pod's logs, so drawing those arrows would connect everything to everything. Each service wears its own IAM role (Pod Identity), and default-deny NetworkPolicies allow only the arrows shown here. Terraform also builds the VPC, subnets and NAT that all of this sits inside.
